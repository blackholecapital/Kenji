# Kenji deployment boundary

> **MANDATORY — READ BEFORE CHANGING OR DEPLOYING THIS REPOSITORY.**

Kenji is a sovereign, self-contained product repository. Its application code, deploy scripts, Wrangler configs, migrations, queues, workers, and deployment helpers must live in this repository.

## Hard boundary

A Kenji deploy must **not**:

- import, execute, patch, copy from, or depend on scripts in `blackholecapital/cloudflare-platform`;
- change or deploy the `cloudflare-platform` Worker, Pages project, routes, bindings, repository, or configuration;
- modify another product repository to make Kenji work;
- shut down or reconfigure shared voice/video runtimes used by other products.

Kenji may consume already-existing shared infrastructure through stable external contracts only.

## Allowed shared resources

Kenji may reference these already-provisioned shared resources without owning their source repository:

- Cloudflare account resources such as the existing `default_secrets_store`;
- centralized secret names already provisioned in that store;
- `blackhole-video-worker` through its committed service-binding contract;
- the shared EILA voice/runtime endpoint through its committed runtime contract;
- Twilio, Deepgram, Resend, LiveKit, LemonSlice and HighLevel through Kenji-owned adapters.

Using a shared Cloudflare resource is **not permission to execute code from another repository**.

## Deployment rule

All Kenji deployment commands must run from the Kenji checkout and use only files committed to Kenji.

```text
Kenji repo
  -> Kenji deploy script
  -> Kenji-owned deploy-with-secrets-store helper
  -> Cloudflare account API / existing Secrets Store
  -> Kenji workers and bindings
```

The `cloudflare-platform` repository is a separate product/platform module and is outside the Kenji deployment boundary.

## Current local helper

Secrets Store bindings are generated by:

`./scripts/deploy-with-secrets-store.mjs`

This helper discovers the existing Cloudflare Secrets Store by name, generates a temporary Wrangler config inside the Kenji working tree, deploys the requested Kenji Worker, and deletes the temporary file. Secret values never enter GitHub.

## Agent rule

If a future task appears to require changing another repository, stop. Fix the Kenji adapter or ask for explicit authorization instead of crossing the repository boundary.
